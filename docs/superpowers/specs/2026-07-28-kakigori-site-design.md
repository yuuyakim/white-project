# White Project（かき氷専門店）HP 設計書

作成日: 2026-07-28
更新日: 2026-07-28（ブランド情報とデザイン方針を追加、間借り営業の実態を反映）

## 目的

かき氷専門店「White Project」の紹介サイトを制作する。**固定店舗を持たず、曜日によって間借り先が変わる**営業形態のため、「今日どこで食べられるか」を最短で伝えることをサイトの第一の仕事とする。あわせて、メニューの世界観を伝え、イベント出店の相談窓口になる。

## 店舗の実態

Instagram（@whiteproject_kakigori）から確認した内容。**すべて店主への確認が必要な暫定情報**として扱う。

- 屋号: White Project（かき氷専門店）
- 2026年6月から間借りでの営業を開始
- 出店場所は2箇所を曜日で使い分ける
  - 月〜土 18:30–21:30 … 赤鰐
  - 日 12:00–19:00 … cafe KAKAOc
- エリア: 名古屋
- メニューは季節の果物が主役。桃、桃アールグレイ、さくらんぼ、いちご、ドリアンなどが確認できる
- SNSはInstagramとThreads

**未確定事項:** 各出店先の正確な住所、定休日、価格、支払い方法、駐車場。これらは実装上プレースホルダを置き、`// TODO` を残す。

## 前提

- 技術スタック: Astro 7（静的サイト生成）。当初Astro 6を想定していたが、実装時の最新安定版7.1.4を採用した。Content CollectionsのAPIは6から変更がない。7で変わるのはRustコンパイラがHTMLの閉じタグ省略を許容しない点と、`compressHTML` の既定値が `'jsx'` になり行間の空白が除去される点の2つで、いずれも実装計画に対応を記載済み
- コンテンツ更新: 制作者がMarkdownを編集してGitにpushする。店主はCMSを触らない
- 想定規模: 静的4ページ + お知らせ記事

## ページ構成

| URL | 内容 |
|---|---|
| `/` | トップ。ヒーロー、本日の出店、看板メニュー、お知らせ |
| `/menu` | メニュー一覧。定番と季節限定を分けて表示 |
| `/venues` | 出店情報。2会場それぞれの曜日・時間・地図 |
| `/news` | お知らせ一覧 |
| `/news/[slug]` | お知らせ詳細 |
| `/contact` | お問い合わせ・イベント出店の依頼 |
| `/404` | 404ページ |

「アクセス」ではなく「出店情報」とする。単一の店舗住所が存在しないため、来店者が知りたいのは「場所」ではなく「曜日と場所の組み合わせ」である。

## デザイン方針

参考として提示された Bollina のサイトの方向性（余白の広さ、縦組みの日本語、細い書体、ソフトなグラデーション、装飾の少なさ）を踏襲する。

### コンセプト

**「白の余白に、氷だけが色を持つ」**

屋号が White Project であること、かき氷が白い塊であることから、サイトの地は白と水色だけで構成する。**彩度のある色はかき氷の写真からしか出さない。** ブランドカラー以外の第2アクセントカラーを持たないことで、果物の色が写真から立ち上がる。

### カラー

ロゴ画像からサンプリングした実測値を基準にする。

| トークン | 値 | 用途 |
|---|---|---|
| `--paper` | `#FCFDFD` | 地の色。わずかに青みのある白 |
| `--ice` | `#5ABDDD` | ロゴのブルー。**装飾専用**。白地とのコントラスト比2.1のため文字色には使わない |
| `--ice-deep` | `#1C6B85` | リンク・小見出し。白地とのコントラスト比5.9でAA適合 |
| `--mist` | `#E4F2F8` | グラデーションの終点、淡い面 |
| `--sumi` | `#1B2328` | 本文。青みを含んだ黒 |

### タイポグラフィ

3つの役割に別々の書体を割り当てる。

| 役割 | 書体 | 理由 |
|---|---|---|
| ディスプレイ（縦組みコピー・見出し） | Shippori Mincho 400 | 明朝の縦画が氷の削り目と響く。Noto Serif JP より筆致が残り、既製感が出にくい |
| 本文 | Zen Kaku Gothic New 300/400 | 角に丸みのあるヒューマニスト。手描きのロゴと質感が合う |
| 欧文・数字・ラベル | Jost 300/400 | ロゴの "White Project" が幾何学サンセリフのため、それに合わせる |

価格・時刻・曜日ラベルはすべて Jost で組み、数字の見え方をサイト全体で統一する。

### レイアウトの軸 — 縦

かき氷は縦に高い。この形をレイアウトの構造に使う。

- ヒーローのコピーは**縦組み**（`writing-mode: vertical-rl`）で写真の左右に置く
- メニュー写真は 3:4 の**縦長**。商品名も縦組み
- 縦組みを使うのはこの2箇所だけに限定する。それ以外は横組み

**枠線と角丸カードを使わない。** 区切りは余白で行い、罫線はヘアラインを必要な箇所のみ。

### 構造

セクション見出しには Jost の小さなラベル（`MENU` `NEWS` `VENUES`）を widely tracked で添える。これは装飾ではなく、そのセクションが何かを示すラベルとして機能する。

### シグネチャー要素 — 「本日の出店」

このサイトで最も記憶に残る要素であり、この店の実態そのものを設計に取り込む部分。

トップページのヒーロー直下に「本日はここにいます」の帯を置く。ブラウザの曜日を読み、`shop.ts` の会場データから今日の出店先を出し分けて強調表示する。静的サイトのためビルド時ではなく**クライアント側の小さなスクリプト**（外部依存なし、20行程度）で判定する。JavaScriptが無効な環境では両会場を並べて表示する。

来店検討者が最初に知りたい情報がファーストビューで解決し、かつ「日替わりで場所が変わる店」という個性がそのまま画面の仕掛けになる。

### モーション

- ページロード時、ヒーローの縦組みコピーが下から淡く立ち上がる（0.1秒ずつずらす）
- スクロール連動の出現はセクション単位でごく控えめに
- `prefers-reduced-motion: reduce` では全アニメーションを無効化する

## データ設計

### 会場（`src/data/shop.ts` の `venues`）

間借り営業のため、住所は単数ではなく会場の配列として持つ。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | `akawani` など。アンカーリンクに使う |
| `name` | string | 会場名 |
| `days` | number[] | 出店曜日。0=日曜〜6=土曜。「本日の出店」判定に使う |
| `daysLabel` | string | 表示用。「月〜土」 |
| `open` / `close` | string | `18:30` 形式 |
| `address` | string | 住所 |
| `mapUrl` / `mapEmbedUrl` | string | Googleマップのリンクと埋め込み |
| `note` | string? | 補足 |

### メニュー（`src/content/menu/`）

1商品1ファイル。季節商品の入れ替えはファイル追加か `available` の切り替えで完結する。

| フィールド | 型 | 説明 |
|---|---|---|
| `name` | string | 商品名 |
| `price` | number | 税込価格（円） |
| `description` | string | 説明文 |
| `image` | image() | `src/assets/images/menu/` 配下 |
| `season` | `'all'` \| `'spring'` \| `'summer'` \| `'autumn'` \| `'winter'` | 提供期間 |
| `available` | boolean | 現在提供中か |
| `order` | number | 表示順 |

### お知らせ（`src/content/news/`）

ファイル名は `YYYY-MM-DD-<slug>.md`。URLは日付を除いた `/news/<slug>`。

| フィールド | 型 | 説明 |
|---|---|---|
| `title` | string | 見出し |
| `date` | date | 公開日。一覧は降順 |
| `category` | `'休業'` \| `'新メニュー'` \| `'出店情報'` \| `'その他'` | 分類 |
| `draft` | boolean | trueなら本番ビルドから除外 |

「イベント」を「出店情報」に変更した。間借り営業では出店先の変更が最も頻度の高い告知になる。

### 店舗情報（`src/data/shop.ts`）

屋号・説明・連絡先・SNS・会場配列を保持する唯一の情報源。トップ、出店情報、フッター、構造化データがここを参照する。

## コンポーネント設計

データ取得はページ側で行い、コンポーネントはpropsを表示するだけに徹する。

- `BaseLayout.astro` — head、meta、OGP、JSON-LD、Header/Footer
- `NewsLayout.astro` — お知らせ詳細の本文枠
- `Header.astro` — 中央にロゴ、左にナビ。ヒーロー上では地を透過させる
- `Footer.astro` — 会場要約とSNS
- `TodayVenue.astro` — シグネチャー要素。曜日判定と会場の出し分け
- `VenueCard.astro` — 会場1件の表示。`/venues` とトップで共用
- `Hero.astro` — 縦組みコピーと全幅写真
- `MenuCard.astro` — 縦長写真と縦組みの商品名
- `NewsList.astro` — お知らせ一覧。件数上限をpropsで指定

## 画像の扱い

- `src/assets/images/` — メニュー写真、ロゴ。Astro Imageで圧縮・WebP化
- `public/` — OGP画像とfaviconのみ

ロゴは `src/assets/images/brand/logo-on-white.png`（白地・青ロゴ）と `logo-on-blue.png`（青地・白ロゴ）の2種を配置済み。ヘッダーは前者を使う。

## エラー処理・検証

- コンテンツのスキーマ違反はzodがビルド時に検出しビルドを失敗させる
- 存在しないURLは `404.astro` で受ける
- `draft: true` のお知らせは本番ビルドから除外
- 「本日の出店」はJS無効時に全会場を表示するフォールバックを持つ

## スコープ外

- お問い合わせフォームのバックエンド（メールとSNS導線で代替）
- 多言語対応、EC機能、予約機能
- 自動テスト（表示のみのため、ビルド成功と目視確認で検証する）
- 出店カレンダーのUI（曜日固定の運用のため、例外はお知らせで告知）

## 成功基準

- 全7URLが表示され、ビルドと型チェックが通る
- トップを開くと、今日の出店先が判別できる
- JavaScriptを無効にしても両会場の情報が読める
- 会場情報を `shop.ts` の1箇所で変更すると全ページに反映される
- Markdownファイルを1つ追加するだけでメニューまたはお知らせが増える
- 375px幅で縦組みを含めレイアウトが破綻しない
- `prefers-reduced-motion: reduce` でアニメーションが止まる
